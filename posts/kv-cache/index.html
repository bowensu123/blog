为何缓存,缓存何物

从自回归生成的重复计算,到一道主宰推理成本的显存公式

大语言模型生成文本的方式是自回归的:模型一次只吐出一个 token,再将其接回输入,据以生成下一个。朴素地实现这一过程,意味着每生成一个新 token,都要把整段已有序列重新送入网络——第一百个 token 诞生时,前九十九个 token 的全部注意力都被重算一遍。计算量随生成长度呈平方级累积,绝大部分是冗余的。

症结的破解,藏在注意力机制的一个朴素事实里。每个 token 进入注意力层时,会被投影为三个向量:查询 Q、键 K、值 V。当前 token 用它的 Q 去和所有历史 token 的 K 做匹配,再据此加权聚合它们的 V。关键在于:对一个已经处理过的 token,它的 K 与 V 是恒定的——无论其后再接什么,都不会改变。

§
KV Cache 的全部精神,可凝为一句:已算之物,不再重算。它是一次以空间换时间的经典权衡。

于是有了 KV Cache:把每一层、每个已生成 token 的 K 与 V 缓存于显存。生成新 token 时,只需为它自己计算 Q、K、V,将新的 K、V 追加入缓存,再令其 Q 与缓存中全部 K、V 作注意力。每一步的代价,遂从"重处理整个序列"坍缩为"处理一个 token,外加一次查表"。

那道主宰一切的公式

天下无免费之事。这份加速的代价是显存。一个请求所占的 KV Cache,其字节数可精确写出:

定义 0.1 — KV Cache 显存占用
Bytes=2⏟K, V×L×S×nkv×dhead×B×p\text{Bytes}=\underbrace{2}_{K,\,V}\times L\times S\times n_{kv}\times d_{head}\times B\times pBytes=K,V2​​×L×S×nkv​×dhead​×B×p
L 层数,S 序列长度,n_kv 为 KV 头数,d_head 每头维度,B 批大小,p 每元素字节数。开头之 2,因 K 与 V 须分别存储。

这道公式是整篇文章的主线。后面要讲的每一项技术,无非是在攻击其中某一个因子,或优化这批字节在存储层级中的安放方式。它随序列长度与并发数线性膨胀;在长上下文之下,它甚至超过模型权重本身。

实例 · 让数字说话取 Llama-2-7B(MHA):L=32,n_head=32,d_head=128,FP16(p=2)。单个 token 的缓存为 2×32×32×128×2=1 MB2\times32\times32\times128\times2=1\,\text{MB}2×32×32×128×2=1MB。于是 4096 token 的上下文需 约 4 GB;当 batch=8,飙至 32 GB——已逼近乃至超过 7B 权重本身的约 14 GB。缓存,而非权重,成了长上下文服务的真正瓶颈。

全文的地图

面对这道公式,优化分作泾渭分明的两途。其一,把缓存做小:通过共享、压缩、降精度、或干脆少存,削减公式中的因子——此途多需改动模型结构。其二,把缓存管好:数据量不变,而优化其在显存中如何安放、如何跨请求复用、如何在存储层级间迁移——此途纯属推理引擎之事,不动模型分毫。

何以独惠解码?——算术强度之辩

欲明此类技术之价值,须辨 prefill 与 decode 之别。解码阶段每步仅生成一个 token,其计算量微乎其微,却须将整个 KV Cache 自显存读出方能作注意力。其算术强度(每字节访存所摊的浮点运算)极低,是彻底的访存受限(memory-bound)。

命题 1.1 — 解码受限于带宽
tdecode-step≈KV Cache 字节数显存带宽t_{\text{decode-step}}\approx\frac{\text{KV Cache 字节数}}{\text{显存带宽}}tdecode-step​≈显存带宽KV Cache 字节数​
解码每步耗时近似正比于缓存大小。故缓存缩小 4×,解码吞吐可近似提升至 4×——收益源于"少搬字节",而非"少算"。
洞见这解释了一个常令初学者困惑之事:GQA 几乎不减少 FLOPs,为何却能大幅加速?因为它压根不在算力上较劲,而在每一步解码须搬运的字节数上。瓶颈被挪走了。

MQA — 极简的共享

Shazeer 于 2019 年提出。所有 Query 头共享同一组 K、V,nkv=1n_{kv}=1nkv​=1。缓存压至 1/h1/h1/h,最为彻底。代价是表达力的明显折损——在大模型上,质量下降可被感知。

GQA — 折中,且可低成本迁移

Ainslie 等于 2023 年提出。将 hhh 个头分作 ggg 组,组内共享一组 K、V,介于 MHA(g=hg{=}hg=h)与 MQA(g=1g{=}1g=1)之间。其真正的工程价值,在于一项迁移之术:

洞见 · Uptraining已训成的 MHA 模型,可将同组各头的 K/V 投影做均值池化以初始化 GQA,再以约原预训练 5% 的算力继续训练,质量即可基本恢复。这使 GQA 近乎零成本落地,遂成今日开源模型之标配。

MLA — 低秩压缩的潜向量

DeepSeek-V2 之创制。它不走共享之路,而行低秩压缩:将每个 token 投影为一个低维潜向量 ckv∈Rdcc_{kv}\in\mathbb{R}^{d_c}ckv​∈Rdc​(其中 dc≪h dheadd_c\ll h\,d_{head}dc​≪hdhead​)存入缓存,作注意力时再以上投影矩阵还原各头的 K、V。

式 1.2 — MLA 的压缩与还原
ckv=WDKVht,k(i)=WiUKckv,v(i)=WiUVckvc_{kv}=W^{DKV}h_t,\qquad k^{(i)}=W^{UK}_i c_{kv},\quad v^{(i)}=W^{UV}_i c_{kv}ckv​=WDKVht​,k(i)=WiUK​ckv​,v(i)=WiUV​ckv​
仅缓存低维 c_kv,而非 h 组高维 K/V。上投影矩阵 W^{UK}、W^{UV} 可被吸收进相邻权重,推理时几乎不增算力。
陷阱 · 解耦 RoPE低秩压缩与旋转位置编码(RoPE)不可交换——RoPE 须作用于真正的 K,而 MLA 缓存的是压缩前的 c_kv,二者无法直接相容。DeepSeek 之解,谓之 decoupled RoPE:额外辟出一小束专司位置的维度,与压缩部分解耦并行。此乃 MLA 实现中最易疏漏之处。

矩阵吸收:MLA 不增算力的玄机

读者或疑:还原 K、V 既需上投影,岂不徒增计算?玄机在于矩阵吸收。注意力中 q⊤k=q⊤WUKckvq^\top k = q^\top W^{UK} c_{kv}q⊤k=q⊤WUKckv​,可将 WUKW^{UK}WUK 预先并入 Query 投影 WQW^QWQ,令 W~Q=(WUK)⊤WQ\tilde W^Q = (W^{UK})^\top W^QW~Q=(WUK)⊤WQ;输出端 WUVW^{UV}WUV 同理可并入输出投影。如此,上投影从未在运行时显式发生,缓存却始终只是那一个小小的 ckvc_{kv}ckv​。

SECTION 02

量化降精度

向 precision 一项开刀 —— 与结构正交的乘性优化
十六位浮点存的本就不是精确值,那为何不用更少的位?
图 2.1位宽愈低,单个数值占用愈少

前一章削的是缓存里 K、V 的数量;这一节削的是每个数值的位宽。量化将 K、V 从 FP16/BF16 的十六位,映射至 INT8、FP8 乃至 INT4。它直击公式中的 ppp 项,且因其作用于"每个数",故能乘性地叠加于任意结构(GQA、MLA)之上——这是它最可贵的品性。

量化的基本算术

以非对称整数量化为例,将浮点张量 xxx 映射至 bbb 位整数:

式 2.1 — 仿射量化
s=max⁡(x)−min⁡(x)2b−1,z=⌊−min⁡(x)s⌉,q=⌊xs⌉+zs=\frac{\max(x)-\min(x)}{2^b-1},\quad z=\Big\lfloor-\frac{\min(x)}{s}\Big\rceil,\quad q=\Big\lfloor\frac{x}{s}\Big\rceil+zs=2b−1max(x)−min(x)​,z=⌊−smin(x)​⌉,q=⌊sx​⌉+z
s 为缩放因子,z 为零点。反量化 x̂ = s·(q − z)。对称量化则令 z = 0,牺牲一点范围利用率换取无零点的快路径。

真正的难处:离群值

KV Cache 量化远较权重量化棘手,根由在离群值:K、V 中少数通道的数值幅度远逾其余。若按整张量统一量化,这些离群值会把 sss 撑得极大,致使绝大多数寻常数值的有效位数被吞噬殆尽。量化的粒度遂成胜负手。

表 2.1 — 量化粒度的权衡
粒度一个 scale 所辖抗离群开销
per-tensor整张量最弱最小
per-token每 token 一组中小
per-channel每通道一组强中
per-group通道内再分小组最强较大
洞见 · KIVI 之策KIVI 的核心观察是:K 的离群值固着于特定通道,而 V 无此规律。故最优之策非一刀切,而是K 按 per-channel、V 按 per-token 分而治之。这一不对称处理,是高质量 2-bit KV 量化得以成立的关键。

FP8 与 INT8:硬件的视角

  • INT8:均匀量化,需 scale 与零点,对离群值敏感;然定点运算在旧硬件上更普及。
  • FP8:有 E4M3(四位指数、三位尾数,范围窄而精度高)与 E5M2(范围宽而精度低)两式。浮点天然的非均匀分布更能从容容纳离群值;Hopper(H100)及其后世具原生 FP8 张量核,正使其成为推理之首选。
陷阱 · 反量化的隐性开销解码本是访存受限,量化减少搬运字节,本应提速;然每次注意力前,须将低位整数反量化回浮点。倘若此步未与注意力 kernel 融合(fused),额外的访存与转换反可吞掉全部收益。上乘的实现(如 FlashAttention 的量化变体)会将反量化压入 kernel 之内,与计算一气呵成。

量化亦是全文少数既可于推理时施加、又可结合训练的技术。正因如此,它在"改结构"与"改引擎"两途之间居中而立——这一点,尾章还将重提。

所省者
按位宽线性缩小:INT8 减半,INT4 减至四分之一。无需改动架构,推理时即可施加,且可叠加于 GQA、MLA 之上。
所偿者
精度损失随位宽递减而增;离群值须以细粒度驯服;反量化非经 kernel 融合则反受其累。

少存 token

缓存驱逐与稀疏 —— 把预算从 O(S)O(S)O(S) 钉为 O(1)O(1)O(1)
序列再长,真正值得缓存的 token 其实没几个。
图 3.1保留开头 sink 锚点,方得流式稳定

前两章削的是每个 token 的占用;这一节削的是 token 的数目。其立论是:注意力本质稀疏,少数 token 贡献了绝大部分注意力质量。既如此,何不只缓存这少数,从而将缓存复杂度由 O(S)O(S)O(S) 一举钉为固定预算 O(1)O(1)O(1)?

为何不能径直"只留最近 N 个"

最朴素之法是纯滑动窗口,只保留最近的 N 个 token。然实践中,一旦最早的 token 被挤出缓存,模型质量便断崖式崩塌。StreamingLLM 给出了它的数学解释,根源在 softmax 的归一化约束:

式 3.1 — 注意力的归一化约束
∑j=1isoftmax⁡ ⁣(qi⋅kj)=1\sum_{j=1}^{i}\operatorname{softmax}\!\big(q_i\cdot k_j\big)=1j=1∑i​softmax(qi​⋅kj​)=1
注意力权重被强制求和为一。纵使当前 token 并无实质可关注之物,这部分"多余"的注意力也必须有所倾倒。

模型于是习得一桩诡计:把这些多余的注意力,固定倾倒于序列最初的几个 token 之上——是为 attention sink(注意力沉没)。这几个 token 内容上往往无足轻重,却充当了 softmax 的泄压之阀。一旦它们被驱逐,注意力分布被迫重组,模型遂崩。

二法分陈

  • StreamingLLM — 永久保留开头四个 sink token,外加最近窗口,中间尽弃。如此,模型可于近乎无限长的流式输入上稳定生成,而显存恒定。
  • H2O(Heavy-Hitter Oracle) — 立基于"少数 heavy hitter 主导注意力"之察。为每个 token 维护一份累计注意力分数 ∑tat,j\sum_t a_{t,j}∑t​at,j​,缓存既满,贪心驱逐分数最低者,留 heavy hitter 与近期之 token。其择留乃内容动态所定,或为序列中部的某个题眼。
陷阱 · 位置编码须重定StreamingLLM 实现中最易错之处:缓存内的 token,须按其在缓存中的相对位置重新赋予位置编码,而非沿用其在原序列中的绝对位置。否则中间一段被驱逐后,位置序列出现空洞,位置编码错乱。

SECTION 04

分页管理显存

PagedAttention —— 借虚拟内存之智,灭碎片之患
缓存的麻烦,一半在它太大,一半在它太乱。
图 4.1连续预留之浪费,对分页之紧致

至此,我们转入"把缓存管好"之途。本途不削缓存中分毫数据,而专攻其安放、复用与迁移。开篇即是奠基之作——PagedAttention(vLLM,2023)。它不减一字节缓存,却将显存利用率由传统之二三成,提至近乎满载,从而在同一张卡上服务数倍的并发。

连续分配的两种碎片

传统之法,按 max_seq_len 为每个请求预留一整块连续显存。祸患有二:

  • 内部碎片 — 实际生成长度远短于预留,中间一大段预留却终未用上。此为损耗之大宗。
  • 外部碎片 — 各请求预留块大小参差,释放后留下难以再利用的空隙。

分页之机

PagedAttention 将每个序列的 KV Cache 切作固定大小的块(block),通常容 16 或 32 个 token。一张块表维护逻辑块至物理块的映射,与操作系统的页表如出一辙。

命题 4.1 — 内部碎片之界
每序列内部碎片  <  block_size  个 token\text{每序列内部碎片}\;<\;\text{block\_size}\;\text{个 token}每序列内部碎片<block_size个 token
块愈小,碎片愈微,然块表愈大、kernel 寻址愈繁。16/32 乃实测之平衡。
  • 物理块无须连续,按需分配,内部碎片遂被限于一块之内。
  • 注意力 kernel 须改写为能从非连续的物理块中聚集(gather)K、V——此即"Paged"之名所系,亦其工程之核。
洞见 · 写时复制beam search、并行采样等场景下,多个序列共享同一前缀。分页令它们共享物理块,仅当某序列将于分叉处写入时,方复制该块——与操作系统的 fork/copy-on-write 别无二致。此机制,正是下一章"前缀缓存"得以成立的底层基石。

定制注意力 kernel 之繁复;块表间接寻址的微小开销;block_size 需调优。

SECTION 05

跨请求复用

前缀缓存 —— 相同的开头,只算一次
成千上万的请求共享同一段开头,何必each都重算一遍?
图 5.1多请求共享前缀,墨色部分只算一次

海量请求往往共享相同的开篇——同一段 system prompt、同一组 few-shot 示例、同一篇被反复叩问的文档。前缀缓存将这段公共前缀的 K、V 算定后存留,后继命中之请求径直复用,跳过对它的重复 prefill。这一节所省者,非显存,而是计算。

何以前缀须"精确而对齐"

K、V 是位置相关的——同一 token 处于不同位置,所算出的 K、V 不同。故复用之前提极苛:两请求须自第零个 token 起,逐 token 完全相同;但有一处相异,其后的 K、V 尽数失效。这是 token 级、前缀对齐的匹配,不可跳跃,不可自中段起。

两种实现:哈希与基数树

表 5.1 — 前缀缓存的两种组织
方案机制共享粒度代表
Hash 前缀对固定前缀分块哈希,查表命中块级,宜固定模板vLLM APC
RadixAttention以基数树组织全部请求前缀,自动共享最长公共路径动态细粒度,宜对话树SGLang

RadixAttention(SGLang)是更通达之方:将所有活跃序列的 token 路径组织为一棵基数树,新请求沿树匹配最长公共前缀,自动复用相应缓存块,并以 LRU 驱逐冷僻枝节。多轮对话、共享示例、树状采样等繁复的共享结构,皆被它从容收纳。

洞见 · 收益落于何处前缀缓存优化的是 prefill 计算,直降 TTFT(首 token 延迟)。它丝毫不触及 decode——其后逐 token 之生成,该多慢仍多慢。故于"长前缀、短续写"之境(RAG、冗长 system prompt)收益至巨,于"短前缀、长生成"则几近无感。

它构筑于 PagedAttention 的块共享之上:命中之前缀,径直挂上既有物理块(以写时复制护持),无须重算,亦不重复占用显存。它还须与 chunked prefill 协同,免得冗长前缀的预填充阻塞他者之解码。

所得者
高重复前缀之境,TTFT 与 prefill 算力大减;多租户共享 system prompt 时收益尤著。
所偿者
收益全系于命中率,前缀纷杂则近乎无用;须维护匹配结构(树/哈希)与驱逐之策。

SECTION 06

卸载与集群调度

分级存储与 PD 分离 —— 以带宽换容量,以分工逐瓶颈
显存装不下,就让缓存在存储层级之间流动起来。
图 6.1GPU→CPU→磁盘的分级存储与带宽落差

当 KV Cache 大至显存不能相容,与其有损地削减,不如将一时用不到者,迁往更广而更缓的存储——是为以带宽换容量。在集群之尺度上,更可将 prefill 与 decode 拆分,各就其最适之硬件。这一节登抵全文之顶:系统与集群层面的缓存治理。

分级卸载:先把账算清

GPU 与 CPU 之间经 PCIe 相通(PCIe 4.0 ×16 单向约 32 GB/s),而 GPU 显存带宽则在 TB/s 之列——相差两个数量级。故朴素的卸载极易令搬运沦为瓶颈。其是否划算,系于一条不等式:

命题 6.1 — 卸载划算之条件
tcompute(层)  ≳  ttransfer(层 KV)=该层 KV 字节PCIe 带宽t_{\text{compute}}(\text{层})\;\gtrsim\;t_{\text{transfer}}(\text{层 KV})=\frac{\text{该层 KV 字节}}{\text{PCIe 带宽}}tcompute​(层)≳ttransfer​(层 KV)=PCIe 带宽该层 KV 字节​
唯当一层的计算耗时足以掩盖下一层 KV 的搬运耗时,异步预取方近乎"免费";否则延迟暴露,解码受拖。

工程之要,在 逐层异步预取:计算第 iii 层之际,以独立的 CUDA stream 将第 i+1i{+}1i+1 层的 KV 自 CPU 预取回显存,使传输与计算交叠。FlexGen 更进一步,将权重、KV、激活的卸载,统筹为一个整体的调度优化问题。

PD 分离:拆开相冲的两阶段

prefill 乃计算受限(并行处理整段 prompt,饱食算力),decode 乃访存受限(逐 token 而行,渴求带宽)。二者混于一批,则相互掣肘——冗长的 prefill 阻塞他者之 decode,致延迟抖动。PD 分离(Prefill-Decode Disaggregation)将其部署于不同的 GPU 池:

  • Prefill 池算定 prompt,将所生之 KV Cache 传输予 Decode 池,由其接掌生成。
  • 传输须走高速互联(NVLink / RDMA),否则跨节点搬运 KV 又成新瓶颈。
  • 两池各自独立伸缩、各用其宜的并行策略,分头榨干各自的瓶颈资源。
洞见 · 以 KV 为中心的架构前沿如 Mooncake(Kimi),将 KV Cache 抽象为一座独立的分布式存储池,跨请求、跨节点、跨时间而复用——本质上,是把"前缀缓存 + 卸载 + PD 分离"熔铸为一套以 KV 为中心的服务架构。此乃当下大规模推理系统演进之重心。
所得者
突破单卡显存之限,支撑超长上下文与超大并发;PD 分离消弭阶段间的相互干扰,增益集群吞吐与延迟之稳。
所偿者
卸载受制于 PCIe 带宽,预取未掩则拖慢延迟;PD 分离引入跨节点传输与繁复调度,须高速互联为之撑持。

全景与系统架构

结语

两途归一,与一个旧问

KV Cache 究竟是不是模型结构的一部分?

讲到这里,可以收个尾了。所有技术,终归两途。"做小"一途(第一至三章)改的是缓存里"存多少",其中共享/压缩与少存,皆触动模型结构,须重训,且于质量有所取舍。"管好"一途(第四至六章)改的是缓存"怎么用",纯由推理引擎实现,不动模型权重分毫,数学输出全然不变。

命题 7.1 — 两途之正交

设结构优化为 S\mathcal{S}S,系统优化为 E\mathcal{E}E,则二者可复合而互不相消:显存收益(S∘E)≈收益(S)×利用率(E)\text{显存收益}(\mathcal{S}\circ\mathcal{E})\approx\text{收益}(\mathcal{S})\times\text{利用率}(\mathcal{E})显存收益(S∘E)≈收益(S)×利用率(E)。

故生产之系统(vLLM、SGLang、TensorRT-LLM),恒于左途择一结构,而右途能开者尽开之。

于是回到开头那个最朴素的问题:KV Cache 是模型结构的一部分吗?

答曰:否。KV Cache 本身是推理时的一种优化机制,它不含任何可训练参数,也不改变模型的数学定义——有它无它,模型的输出完全相同(浮点误差不计),区别只在快慢。然而,那些为缓存友好而生的结构设计(GQA、MLA),确确实实改动了模型本身。量化则游移于两可之间。

∎
缓存非结构,然结构可为缓存而改。技术之演进,常在这"机制"与"结构"的往复借力之间。

这正是这篇文章想说的核心:KV Cache 是一道桥,一端系于模型的数学,一端系于系统的工程。读懂了它随哪些因子膨胀,也就读懂了这两端如何彼此牵引、共同塑造了今日大模型推理的全部形态。
